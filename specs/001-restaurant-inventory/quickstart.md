# Quickstart validation (целевое состояние)

Команды ниже начнут работать после задач setup/deploy. Документация сейчас не утверждает существование Docker-кода.

1. Скопировать `.env.example` в `.env`, локально задать demo access code и серверный адрес. Секреты не отправлять в чат и Git.
2. `docker compose --profile demo up -d --build --wait`; проверить `https://<host>/actuator/health/readiness` и состояние миграций.
3. Зайти в браузер, открыть склад, зарегистрировать две партии муки с разным сроком и один недостающий ингредиент.
4. Создать заказ из двух блюд. Проверить accepted, точное FEFO-списание и обновлённые остатки.
5. Повторить тот же HTTP-запрос с тем же ключом: прежний результат без новых движений. Изменить тело при том же ключе: 409.
6. Создать заказ с дефицитом: rejected, 0 новых списаний, блюдо в стоп-листе с причиной. Добавить поставку: блюдо выходит.
7. Проверить карточку hot offer: причина и ближайший срок; недоступное блюдо не предложено.
8. Запустить управляемый simulator-сценарий; увидеть обновление открытой вкладки и остановить simulator — ручной ввод остаётся работоспособен.
9. Перезапустить `api`/`postgres` без удаления volumes; убедиться, что заказы и движения сохранились.
10. QA выполняет гонки из `docs/QA.md`, сохраняет evidence и отмечает реальные результаты. README обновляется URL/SHA только после PASS.
