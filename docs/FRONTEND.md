# Frontend и UX: веб-интерфейс FreshLine

Владелец: backend fullstack при дизайне-направлении lead. Контракт: `contracts/openapi.yaml`; состояния/тексты должны соответствовать фактическим серверным результатам. Это не экран «AI dashboard» с случайными карточками: интерфейс показывает решения менеджера по конкретным партиям и блюдам.

## Информационная архитектура

1. **Обзор** — главный ответ за 10 секунд: пригодные партии, сколько истекает сегодня/3 дня, блюда в стоп-листе, 3 предложения, последние 5 событий. У каждой цифры ссылка на источник.
2. **Склад** — таблица ингредиентов с общим/пригодным остатком, раскрываемые партии с поставкой, сроком и движениями. Фильтры «сегодня», «≤3 дней», «просрочено», поиск. Ясно показывать единицу и местную дату.
3. **Поставки** — мастер: номер/дата → строки/количество → изготовлено + срок или дата с этикетки → сводка → подтверждение. Не считать введённую форму сохранённой до ответа сервера. Дубликат объяснить и предложить открыть существующий приход.
4. **Заказы** — несколько блюд/порций, предварительная подсказка о возможном дефиците, итоговая серверная проверка, accepted или refused со списком недостающих ингредиентов. Кнопка повторения использует прежний idempotency key лишь для **того же** запроса.
5. **Меню и стоп-лист** — доступные блюда, недоступные с точной причиной; hot offers только из доступных с датами партий и объяснением; закупка с `basis`, не «AI предсказал».
6. **История/демо** — временная шкала поставок/заказов/отказов, кнопки Start/Pause/Reset demo с явным предупреждением о сбросе синтетики, индикатор live/reconnecting. Сброс отдельным admin-only действием только на выделенном demo project.

## Визуальная система

- Тон: ресторанные операции, аккуратный продуктовый интерфейс. Светлый тёплый фон `#F7F5F0`, основной текст `#172B32`, акцент глубокий бирюзовый `#0B6664`, предупреждение янтарь `#B96C16`, критический коралл `#B84035`. Не использовать цвет как единственный носитель статуса.
- Шрифт: интерфейс с кириллицей (например Inter с явной поддержкой); табличные цифры для количеств/дат. 8px spacing scale, минимум 44px touch target, контраст WCAG AA. Не использовать эмодзи как основную иконографию.
- Карточка партии показывает **ингредиент · поставка · остаток/исходное · срок · дней осталось** в одном порядке на всех экранах.
- Два размера: desktop ≥1024 с боковой навигацией и таблицами; mobile 360–767 с нижней/сворачиваемой навигацией и карточками вместо горизонтально обрезанных таблиц. Tablet — промежуточный.
- Пустое состояние рассказывает следующий шаг («Добавьте первую поставку»), загрузка не меняет расположение важных элементов, ошибка показывает действие «Повторить» и request ID. Demo badge всегда виден.
- Никаких декоративных графиков без значимого решения. Разрешён один компактный график риска по дням или столбцы пригодных/истекающих партий с подписанными единицами. Основные данные — читаемые таблицы и карточки причин.

## Поведение и интеграция

- Использовать сгенерированные типы OpenAPI, TanStack Query для snapshots; мутации с idempotency key, safe retry и осмысленным stale state.
- SSE invalidates queries и обновляет timeline. После разрыва `Last-Event-ID`/новый snapshot; скрытая вкладка не запускает безлимитные повторы. Если SSE временно недоступен, UI сообщает «обновление задерживается» и предлагает refresh.
- Дни до истечения клиент может показывать из API `daysRemaining`, но окончательная проверка заказа всегда на сервере. При полуночи обновить stock/stop-list/offers.
- DEMO-доступ: code вводится в форму, сервер выдаёт HttpOnly Secure SameSite session и CSRF; не хранить code в localStorage и не показывать в логах. Публичный просмотр синтетики может быть без входа, запись только с session.
- Клавиатура, focus-visible, labels, aria-live для результата заказа, формат дат/чисел `ru-RU`. Проверить на Chrome и Firefox, 360px и desktop. Никаких ложных success toast до подтверждения commit.

## Проверка готовности

Ручной браузерный smoke после интеграции: поставка → два срока → заказ → FEFO → стоп-лист → hot offer → повтор/ошибка. Playwright — happy path + отказ + keyboard/mobile smoke. Скриншоты на 1440px и 390px, без личных данных. Figma может быть использована для согласования компонентов, но код и контракт — источник фактического состояния; отдельный файл Figma не является gate MVP.
