# Архитектурные решения и открытые допущения

| ID | Решение | Причина / последствие | Дата |
|---|---|---|---|
| ADR-01 | Java 21 + Spring Boot 3.5.16 для API и бизнес-логики | Запрос пользователя; зрелый стек за 5 дней | 12.10 |
| ADR-02 | Модульный монолит, PostgreSQL 17 | Одна ACID-транзакция проверки и списания. DE владеет persistence/migrations; отдельный Python data API здесь не нужен | 12.10 |
| ADR-03 | FEFO по `expires_on,id`, дата срока включительно, local restaurant date | Детерминированность и честная работа с партиями; вопрос эксперту подготовлен | 12.10 |
| ADR-04 | Демо-клиент в отдельном контейнере, HTTP-only, синтетические данные | Проверяет публичный контракт и показывает живой поток, не обходит правила | 12.10 |
| ADR-05 | React/TS/Vite/Chakra UI 3, собственные дизайн-токены | Соответствует рекомендованному стеку кейса, быстрее собрать качественный UI | 12.10 |
| ADR-06 | SSE после G1, `Last-Event-ID` + refresh snapshot | Наглядность без тяжёлого брокера; outbox после commit | 12.10 |
| ADR-07 | HTTPS через Caddy на уже имеющемся VDS, домен по желанию | Достаточен стабильный HTTPS hostname; проверять внешний доступ | 12.10 |
| ADR-08 | Публичный demo только с синтетикой и защищённой записью | Избежать утечки и бесконтрольного спама | 12.10 |

Правило изменения: автор пишет новую строку с эффектом на API/данные/тесты/срок и приносит в интеграционную ветку до изменения общей границы. Устные решения без commit не действуют.
