# Что перенесено из прошлого хакатона

Источники: два экспорта, переданные пользователем 12.10, и публичная история [Seferaki/max-fleet](https://github.com/Seferaki/max-fleet) (543 коммита на момент просмотра). Экспорты не копируются сюда: в них старый продукт, личный контекст и технические логи. Это резюме рабочих решений, а не новые требования «Флагмана».

| Наблюдение | Как применено сейчас |
|---|---|
| Два backend-ноутбука работали по очереди, лимит агента мог оборвать задачу | Для каждой backend-полосы есть commit/push после малого шага, status и безопасный takeover; чаты не являются источником прогресса |
| Git переносит код и файлы, но не историю модели, Docker volumes и секреты | Репо содержит спецификацию/контракт/progress/prompts; seed синтетический, секреты вне Git, backup отдельный |
| Data engineer работал независимо и синхронизировался через свою ветку/PR | DE владеет миграциями/SQL/persistence, общий порт замораживается на G0; интеграция минимум дважды в день |
| QA получал отдельный компактный файл требований и мог начать до кода | `docs/QA.md`, матрица FR→case, fixtures, ручные сценарии и prompt; автоматизацию пишет агент |
| Mock и технический healthcheck нельзя выдавать за реальную приёмку | G1/G2/G3 требуют сквозные реальные Compose/PostgreSQL и проверку браузера по URL; статус NOT RUN честный |
| На прошлом проекте доп. доступы/публичный HTTPS и реальный пользовательский сценарий затянулись | Внешний URL, demo-доступ и проверка с другого устройства начинаются до финального дня, а не после всех фич |
| Человеку нужны короткие, точные действия только для собственных аккаунтов и инфраструктуры | `docs/HUMAN_REQUIRED.md` с конкретным вводом, сроком и независимой работой агента |

Тогдашнее согласие на Go → Python HTTP → PostgreSQL относилось к MAX-боту. Для нынешнего кейса приоритет текущего запроса — Java. Дата-инженер сохраняет независимую зону, но внутри единого Java/SQL приложения. Старые предметные правила (автомобили, фото, MAX IDs) в FreshLine не переносятся.
