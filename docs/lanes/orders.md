Тесты чистой политики изолированы, но конкурентность подтверждается только на PostgreSQL. Изменение `domain` ABI требует короткого сообщения в PR и обновления consumer-тестов до merge.

## Инварианты и критерии

- Сначала сложить потребность всех блюд по ингредиенту. Проверка и списание выполняются на одном снимке внутри транзакции, партии сортируются по `expires_on, id`.
- Дата `expires_on` включительна относительно локальной даты ресторана. Отрицательные/нулевые заказные количества и несовместимые единицы отклоняются до SQL.
- Доменные политики не открывают соединения и не читают системное время напрямую: принимают `Clock`/today и портовые данные.
- Невозможность обеспечить lock order или ledger equality — блокер G1, а не «известное ограничение».

Каждый малый шаг — code commit, [progress](../progress/orders.md) с SHA/командой/результатом и push. При `HANDOFF` журнал должен назвать contract/port SHA, последний проверенный code SHA, незакрытую гонку и **точный следующий тест/файл**. [Правила восстановления](../TEAM_WORKFLOW.md#внезапное-прерывание-и-takeover).
